# Gemini 3.1 Flash-Lite / 3.5 Flash-Lite 실제 발표문 50건 비교

**결론: 이번 표본에서 3.1은 더 저렴하고 조금 빨랐습니다. 다만 두 모델 모두 중요한 의미 오류가 있어, 3.1이 경보 해석에서 3.5와 동등하게 안전하다고 결론 낼 근거는 없습니다. 3.5가 모든 면에서 우수한 것도 아닙니다.**

## 원문과 대조해 확인한 차이

### 3.1에서 확인한 중요한 문제

- **US-15 / 날짜 왜곡**: 원문은 10월 17일 발표, 사건은 다음 월요일 밤부터 화요일입니다. 요약은 `2026년 10월 17일 월요일 밤 ~ 10월 18일 화요일`로 날짜와 요일을 잘못 결합했습니다. 3.5는 월요일 밤~화요일이라는 상대 표현을 보존했습니다.
- **JP-08 / 대상 지역 확대**: 미야자키현 남부 평야부와 니치난·쿠시마 지구는 원문 XML에서 `발표된 경보·주의보 없음`인데, 3.1은 호우주의보가 지속되는 지역으로 넣었습니다. 원본 XML의 Item/Area/Kind와 직접 대조했습니다. 3.5 요약은 북부 평야부만 언급했습니다. XML 평탄화로 결합 구조가 약해진 입력 준비의 영향도 있습니다.
- **JP-01 / 용어 오설명**: 열대저기압을 ‘태풍 중심부에서 강한 바람이 부는 영역’이라고 정의했습니다.
- **US-02 / 행동 요약 변경**: 원문의 차단막 우회·미확인 수심 진입 금지 대신, 요약에는 ‘도로 통제 시 우회 경로 확인’을 추가했습니다. 별도 행동 번역은 금지를 보존했습니다.

### 3.5에서 확인한 중요한 문제

- **US-09 / 특보 종류 혼동**: `Gale Warning`을 전체 번역과 요약에서 ‘강풍주의보’로 옮겼습니다. 용어 설명에서는 ‘경보’라고 해 내부 일관성도 흔들렸습니다. 3.1은 ‘강풍 경보’로 번역했습니다. 한국 제도와 1:1 대응한다는 뜻은 아니며, 원문의 Warning/Watch/Advisory 차이를 보존해야 합니다.
- **US-10 / 거리 단위 오역**: `20 NM`을 ‘20 해일(NM)’로 썼습니다. 올바른 거리 단위는 해리입니다. 3.1은 해리로 옮겼습니다.
- **JP-12 / 없는 행동 추가**: 지진 발생과 쓰나미 우려 없음을 알리는 원문에 대피 지시가 없는데, 설명 필드에서 ‘안전한 장소로 대피하십시오’를 추가했습니다. 3.1은 지진/쓰나미 설명에 머물렀습니다.
- **JP-03 / 시각 역할 오표기**: 경보 하향 발표문에서 XML 배포 시각을 ‘발생일시’로 표시했습니다. 반면 전체 번역에는 경계 레벨 3→2 하향과 1.5km 위험 반경을 보존했습니다.

### 두 모델의 공통 문제와 장점

- 긴 일본 발표문에서 전체 번역 대신 요약에 가까운 문장을 반환해 시각별 예보, 지역별 상태, 일부 수치를 누락했습니다. 3.5도 이런 실패가 있어 최신 모델만으로 해결되지 않습니다.
- 화산 관측보는 두 모델 모두 발생·발표 시각을 대체로 구분하고 높이·방향을 보존했습니다. JP-03에서 3.1 요약은 경계 단계 하향과 1.5km 범위를 잘 남겼지만 3.5 요약은 그 내용을 생략했습니다.
- JP-12/22에서 쓰나미 우려 없다는 부정 표현은 두 모델이 보존했습니다. 미국 풍속의 mph→km/h, 명시적 미국 기온의 화씨→섭씨 표시는 확인한 표본에서 정상 보존됐습니다. 일부는 앱의 공통 후처리 효과이므로 모델 단독 능력으로 해석하지 않습니다.
- 일본어 단어를 ‘대우 주의보’, ‘분연량 중량’처럼 어색하게 번역하거나, 3.5에서 한자/로마자를 섞는 문제가 있습니다. 지명·기상 용어의 고정 사전이 필요합니다.
- 별도 행동 지침이 없으면 null을 반환해야 하지만 본문 행동을 해당 필드에 채운 사례가 있습니다. 이는 필드 계약 불일치이며, 그 문장이 원문에 있는 경우 사실 날조로 세지 않았습니다. 형식 검증 통과는 의미 정확성을 보증하지 않습니다.

이 목록은 개발 에이전트의 1차 의미 검토에서 확인한 사례입니다. 독립 전문가 정답표가 없고 오류 유형별 전수 채점 기준의 일치도도 검증하지 않았으므로, 임의의 ‘정확도 95점’이나 승률은 제시하지 않습니다. 상세 근거는 review_notes.json에 있습니다.

## 해석의 한계

- 50건은 공개 발표 기록이며, 실제 개인이 수신한 문자 50개나 독립된 재난 사건 50개가 아닙니다. 같은 사건의 시각별 갱신·XML 형식 차이가 포함됩니다.
- 경보 외에 주의보·예보·관측·해제도 포함됩니다. AMBER·쓰나미 경보·즉시 대피 명령 표본이 없으므로 해당 유형까지 일반화할 수 없습니다.
- 일본 입력은 XML 텍스트 잎을 추출하면서 계층·속성 단위 일부가 빠졌습니다. 구조를 보존하는 입력으로 재평가해야 합니다. 이 평가만으로 운영 앱의 XML 처리 결함이라고 단정할 수 없습니다.
- 표본당 1회, 한 계정·한 실행 환경입니다. 반복 안정성과 운영 부하·네트워크 차이는 검증하지 않았습니다. 모델 이름은 응답 modelVersion으로 확인했습니다.
- 100개 응답의 번역·요약·설명·행동 필드를 1차 검토하고, 관찰된 중요한 오류의 원문을 재대조했습니다. 이는 재난/언어 전문가의 독립 승인이나 출시 안전성 인증이 아닙니다.

## 앱에 대한 권고

3.1은 비용 절감 후보로 유지할 수 있습니다. 그러나 이번 결과만으로 경보 해석 전체를 3.1로 바꾸는 것은 권하지 않습니다. 먼저 날짜·지역·경보 종류·조건을 구조화하고, 경보 용어와 지명은 사전으로 고정하며, 원문에 없는 행동 추가와 긴 번역 누락을 차단해야 합니다. 그다음 사건 중복을 줄이고 AMBER·쓰나미·즉시 대피·해제를 보강한 자료로 재평가하는 편이 타당합니다.

운영 모델·환경 변수·서버 설정·결제 설정은 변경하지 않았습니다.
