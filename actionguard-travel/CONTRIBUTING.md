# 팀 개발 안내

## 실행

저장소를 받은 뒤 `README.md`의 백엔드/프론트 최초 설치를 각각 진행하세요. `node_modules`, Python 가상환경, 빌드 결과는 업로드하지 않으며 각자 설치합니다. `.env.example`을 복사해 본인 로컬 `.env`를 만들고 실제 키는 별도로 관리합니다.

프론트만 수정할 때도 공식 데이터 조회에는 로컬 FastAPI 실행이 필요합니다. 기본 연결은 프론트 5173 → 백엔드 8000입니다. `frontend/src/services/api.ts`를 통해 API를 호출해 빈 응답·시간 초과·실패 처리를 유지하세요. 개발자의 개인 컴퓨터 주소를 코드에 고정하지 마세요.

## 변경 공유

1. 기본 브랜치에서 작업 브랜치를 만듭니다. 예: `feature/alert-settings`.
2. 담당 화면/기능을 수정하고 관련 테스트와 빌드를 실행합니다.
3. PR에 변경 내용, 확인 방법, 화면이 바뀌면 캡처, 남은 제한을 적습니다.
4. 팀원 검토 후 병합합니다. 기존 저장소의 브랜치 보호·리뷰 규칙이 있다면 우선 따르세요.

API 응답 필드를 바꾸면 백엔드 계약과 프론트 타입·호출부를 함께 수정합니다. 원본 조회 실패를 ‘경보 없음’이나 ‘해제’로 표시하지 않습니다. AI 설명과 공식 지시, 지도 시설과 실제 개방 상태를 구분합니다.

## 커밋 제외

실제 `.env` 및 변형 파일, Gemini/FCM/APNs 키, 기기 토큰 DB, 서비스 계정 JSON, Android/iOS 서명·인증서, 개인정보가 있는 실제 문자·위치·로그는 커밋하지 않습니다. 실수로 올린 키는 파일 삭제만으로 해결되지 않으므로 해당 서비스에서 폐기·재발급하고 팀 관리자에게 알려주세요.

공유 저장소 접근은 GitHub 계정 권한으로 관리합니다. 키를 저장소에 넣어 팀원에게 전달하지 않습니다. 처음 GitHub 로그인·저장소 권한 설정은 각자 계정에서 진행합니다.
