# ActionGuard Travel — 실제 서비스 전환 검토

검토일: 2026-10-14, 기준: 이번 수정이 반영된 `outputs/actionguard-travel`.

## 1. 결론

현재 버전은 **핵심 기능을 연결한 로컬 시제품**이다. 미국·일본 기상 경보를 가져오고 한국어로 설명하는 출발점은 갖췄지만, 아직 실제 여행자의 재난 판단을 지원하는 공개 서비스로 운영할 준비가 끝난 상태는 아니다.

다음 개발의 우선순위는 국가나 화면을 늘리는 것보다 **사용자가 받은 문자 한 건을 정확하게 설명하고, 적용 지역·시각·지시를 보존하며, 실패했을 때도 확인 가능한 정보를 제공하는 것**이다. 권장 순서는 신뢰성 보강 → 비공개 실사용 시험 → 운영 기반 구축 → 편의 기능 확장이다. 이는 제안이며, 이번에 대규모 구조 변경이나 외부 배포를 실행하지 않았다.

검토 범위는 전달용 프로젝트의 백엔드, 두 경보 어댑터, 번역·검증·안내 로직, 계약 모델, React 화면·상태·통신·스타일·설정, 테스트, 실행 안내다. `work/`의 과거 생성 스크립트·복제본과 설치된 외부 라이브러리 전체를 행 단위로 검수한 것은 아니다. 실제 키를 사용한 Gemini 품질 시험, 최신 NWS/JMA 실제 데이터의 종단 간 시험, 실제 휴대전화 및 동시 접속 부하 시험은 이번 검증에 포함되지 않았다.

## 2. API 키는 계속 입력해야 하나?

**아니다. 운영자가 서버에 한 번 설정하면 이용자는 API 키를 입력할 필요가 없다.**

| 구분 | 현재 구현 | 권장 운영 방식 |
|---|---|---|
| Gemini 번역·검증 | 서버가 `GEMINI_API_KEY`를 읽음 | 로컬은 `backend/.env`에 한 번 저장, 배포 서버는 비밀 설정/Secret Manager에 저장 |
| 미국 NWS 조회 | 사용자 키 입력 없음, 서버의 User-Agent 사용 | 서버가 조회하고 캐시 |
| 일본 JMA 조회 | 사용자 키 입력 없음 | 서버가 조회하고 캐시·데이터 형식 변경 감시 |
| 일반 행동요령 | 준비된 자료를 서버가 선택, 별도 AI 호출 없음 | AI 장애 시에도 제공 |

`backend/main.py`는 시작할 때 **그 파일 옆의 `.env`**를 읽는다. `.env.example`을 `.env`로 복사해 키를 입력하고 서버를 재시작하면 같은 설치 폴더에서는 다시 입력할 필요가 없다. 이번에 확인한 전달용 폴더에는 `.env.example`만 있고 실제 `.env`는 없었다. 다른 실행 폴더나 셸에 키가 설정되어 있는지는 확인하지 않았다. 키 값은 읽거나 수집하지 않았다.

반복 입력의 가능한 원인:

- 터미널에서만 임시로 설정하고 새 터미널을 열었다.
- ZIP을 다른 폴더에 풀어 실행했다. 실제 `.env`는 배포 ZIP에서 의도적으로 제외된다.
- 프런트엔드 폴더나 프로젝트 최상위에 설정했지만 서버는 `backend/.env`를 읽는다.
- `.env` 수정 후 서버를 재시작하지 않았다.
- 기존 셸 환경변수가 `.env`보다 우선한다. 현재 `load_dotenv`는 기존 환경변수를 덮어쓰지 않는다.
- 키가 없는 문제가 아니라 사용량 초과·모델 접근 권한 문제다. 키를 다시 입력해도 해결되지 않는다.

개인 테스트용과 서비스 운영용 프로젝트를 분리하고, 운영 키는 프런트엔드 코드·브라우저 저장소·공유 ZIP에 넣지 않는 것이 맞다. Google도 서버를 통한 호출과 비밀 저장소 사용을 안내한다. [Google API 키 안내](https://ai.google.dev/gemini-api/docs/api-key)

현재 `GEMINI_FREE_TIER_CONFIRMED=true`는 운영자가 무료 프로젝트임을 확인했다는 표시일 뿐, Google 결제를 강제로 막는 장치가 아니다. 기본 `AI_DAILY_CALL_LIMIT=40`은 **Google 한도가 아니라 이 앱이 정한 프로세스 전체 한도**다. 캐시가 없는 전체 분석은 번역 1회와 검증 3회로 최대 4회이므로 약 10건이면 소진된다. 실패한 호출도 카운트되며, 서버 재시작 시 초기화되고 여러 프로세스 사이에서는 공유되지 않는다.

무료 API를 유지할지 유료 운영을 허용할지는 별도 결정이 필요하다. 이번에는 결제 설정이나 호출 한도를 바꾸지 않았다. 무료 서비스의 데이터 처리 조건도 확인해야 한다. Google 약관은 무료 서비스 입력·출력이 제품 개선에 사용될 수 있음을 설명하고 민감·기밀·개인정보 제출을 제한한다. 지역별 예외도 있으므로 실제 운영 조건에 맞춰 검토해야 한다. [Google API 약관](https://ai.google.dev/gemini-api/terms), [요금표](https://ai.google.dev/gemini-api/docs/pricing)

## 3. 이번에 수정한 확인된 오류

| 문제 | 변경 | 검증 |
|---|---|---|
| 온도와 같은 숫자가 날짜·인원수에도 있으면 일괄 치환 | 단위가 붙은 온도만 보정. 단위 없는 온도의 화씨 추정은 공식 NWS 경보 문맥에서만 허용 | 14도와 10월 14일·14명이 함께 있는 사례, 일본어/국가 미확정 사례, 명시적 섭씨 표기는 보존 |
| 이미 환산된 풍속 뒤에 km/h가 반복 추가될 수 있음 | 기존 환산 괄호를 함께 갱신하고 단위 없는 숫자는 건드리지 않음 | 단일/범위 풍속을 두 번 처리해도 같은 결과 |
| 음수·소수 일부가 다른 수치로 잘못 매칭될 수 있음 | 숫자 앞 경계 조건 강화 | 14와 -14·0.14, 60과 -60·0.60 구분 |
| 공식 원문 끝 공백을 프런트에서 제거해 공식 연결이 실패할 수 있음 | 공백 여부는 검사하되 서버로는 원문을 그대로 전송 | 끝에 줄바꿈이 있는 공식 경보의 요청 본문 일치 |
| 동일 원문을 직접 입력한 뒤 공식 경보로 선택해도 번역 캐시 공유 | 캐시 구분에 공식 지시·미국 경보 문맥·모델 포함 | 직접 입력과 공식 연결의 지시 번역 결과 분리 |
| 공식 NWS 지역명이 AI 입력에 없으면 정형 정보 우선 검증 실패 | 번역용 구성 원문에 Event/Area/발행·발효·현상 시작·종료·메시지 만료 메타데이터 포함 | 기존 실패 테스트 수정 없이 공식 필드 우선 테스트 통과 |
| 같은 지역에서 경보 찾기를 다시 눌러도 요청하지 않음 | 동일 검색 조건이면 명시적으로 재조회 | 버튼 재클릭 시 API 요청 2회 확인. 서버 120초 캐시는 계속 적용 |
| 번역·검증 실패 시 F3가 실행되지 않음 | 행동지침 요청을 AI 분석과 별도로 시작 | 번역 429 응답이어도 한국어 일반 행동요령 표시 |
| 기본 행동요령에서 조건식 때문에 미국 분기의 앞 문장 소실 | 공통 기본 행동 문장을 유지하고 국가 미확정 입력에 미국 번호를 단정하지 않음 | 기본 안내에 위치 확인·위험 지역 회피 포함 |
| JMA 전체 지역을 요약 문자열로 저장 | 내부 `area`는 모든 지역 보존, `headline`만 요약 | 5번째 이후 시정촌도 검색·검증용 데이터에 남음 |
| JMA 응답 형식 변경/알 수 없는 코드가 경보 없음처럼 처리될 가능성 | 주요 구조 누락·빈 보고서·알 수 없는 경보 코드에 명시적 실패 처리 | 잘못된 응답이 빈 경보 목록으로 통과하지 않는지 확인 |

수정 위치: `backend/core/translator.py`, `backend/main.py`, `backend/adapters/nws.py`, `backend/adapters/jma.py`, `backend/core/guidance.py`, `frontend/src/pages/Flow.tsx`. 회귀 테스트는 `backend/tests/test_api.py`와 `frontend/src/App.test.tsx`에 추가했다.

이 수정은 특정 재현 오류를 막은 것이며, 숫자·문맥·국가 판별 전체가 해결되었다는 뜻은 아니다. 단위가 빠진 직접 입력은 화씨로 추정하지 않으므로 공식 경보 연결 또는 추가 문맥이 필요할 수 있다.

## 4. 실제 사용 전에 남은 필수 과제

P0: 공개 서비스 전 해결할 항목. P1: 비공개 실사용 시험을 하며 우선 개선할 항목. P2: 기본 안정성 확보 뒤 확장할 항목.

| 우선순위 | 발견 사항 / 재현 조건 | 영향과 필요한 변경 | 코드 근거 |
|---|---|---|---|
| P0 | F2에는 `translation`만 보내지만 화면의 핵심은 `summary`, `hazard_explanation`, `instruction_translation_ko` | 본문 번역이 맞아도 사용자가 먼저 보는 요약·지시 번역은 틀릴 수 있다. 실제 노출할 모든 필드를 검증하고 원문 근거와 연결해야 한다 | `Flow.tsx`의 verify 요청, `extractor.py`, `Translation` 모델 |
| P0 | 시간을 여전히 시각 집합으로 비교 | 발령·시작·종료가 뒤바뀌어도 같은 집합이면 놓치고, 날짜/시간대 변환이 맞아도 오류로 볼 수 있다. 역할+날짜+시간대 기반 비교가 필요하다 | `verification.py`의 `en != ko`, `quotes.py` |
| P0 | F3가 단순 키워드로 안내를 선택 | 예를 들어 일본어 ‘쓰나미 우려 없음’에도 津波 키워드 안내가 나올 수 있다. 재난 유형뿐 아니라 부정·발령 상태·적용 조건을 확인해야 한다. 직접 입력이 임의 지시를 공식 명령으로 승격하지 않도록 유지해야 한다 | `guidance.py`의 `any(token in content...)` |
| P0 | 일본 추가 안내는 작성된 일반 문구이며 인용별 근거 연결 없음 | 일반 기상 소개 페이지 링크가 각 행동 문장을 검증해 주지는 않는다. 출처의 특정 절·인용·검토자·검토일과 연결하고 재난안전 전문가 검토가 필요하다 | `JAPAN_GUIDES`, `data/official_guides/guides.json` |
| P0 | 언어로 국가를 추정, 입력 국가가 서버에 전달되지 않음 | 영어로 받은 일본 경보, 한자가 섞인 다른 국가 메시지에서 안내가 잘못 선택될 수 있다. 명시적 국가/지역과 발령기관을 계약에 포함해야 한다 | `Input`, `guidance.py`의 유니코드 범위 판별, `Flow.tsx`의 country 상태 |
| P0 | 조회한 경보의 변경·해제·최신성을 추적하지 않음 | 15분 연결 캐시는 ‘현재도 유효함’의 증거가 아니다. 취소·변경 버전, 최종 확인 시각, 오래된 결과 표시, 재확인 정책이 필요하다 | 두 어댑터의 `records`, `Cache`, `Flow.tsx` |
| P0 | JMA의 여러 보고서를 지역/코드별로 합치며 최신 문서 상태를 완전히 모델링하지 않음 | 최신 전체 해제, 경보에서 주의보로 변경, 이전 코드 누락 사례를 검증해야 한다. JMA ID도 관할지역+코드뿐이라 버전 식별이 부족하다. 보고시각을 `effective`로 재사용하는 의미도 분리해야 한다 | `jma.py`의 `latest`, `id`, `effective` |
| P0 | 외부 공개용 접근 제어·사용자별 제한 없음 | 누구나 번역 API를 호출해 공유 호출량을 소진할 수 있다. CORS는 인증이 아니다. 공개 전 사용자/세션별 속도 제한, 입력·동시 처리 한도, 관리자 구분, 비용 제한이 필요하다 | `main.py`, `gemini.py` |
| P0 | 실경보 정답 데이터와 실제 Gemini 종단 간 검증 미실시 | 모의 테스트가 통과해도 위험한 번역 누락·오탐률을 알 수 없다. 영어/일본어 실제 경보 기반 정답셋과 전문가 판독 비교가 필요하다 | 현재 테스트는 대부분 모의 응답·규칙 테스트 |
| P1 | 검증 불가·미해결 상태가 화면에서 대부분 숨겨짐 | 내부 표를 다시 노출할 필요는 없다. ‘자동 확인을 끝내지 못했어요’ 정도의 짧은 상태로 미검증을 정상 완료와 구분해야 한다. 오류 두 개도 입력 순서보다 행동 위험 순서로 골라야 한다 | `Flow.tsx`의 `confirmedIssues`, 완료 배지 |
| P1 | 미국은 좌표 또는 주 전체, 일본은 관할 지역 조회 | 일본의 특정 시정촌 선택, 여행지/숙소 저장, 적용 지역 내부 여부가 부족하다. 단순 거리 반경과 실제 경보 영향 구역을 구분해야 한다. NWS 영역/zone 자료와 일본 행정구역을 활용하되 근거 없는 정밀도를 주장하면 안 된다 | `Flow.tsx`, 두 어댑터 |
| P1 | 한 분석에 AI 최대 4회, 전역 잠금으로 요청을 직렬 처리 | 여러 사용자가 접속하면 대기시간이 길어진다. 호출 단계·정확도를 측정하고 작업별 중복 억제, 제한된 동시 처리, 시간 제한, 중단·재시도를 설계해야 한다. 검증을 무조건 줄이는 방식은 피한다 | `main.py`의 `analysis_lock`, `gemini.py`의 `lock`, `extractor.py` |
| P1 | 경보 기록·캐시·일일 한도가 메모리에만 존재 | 재시작 시 초기화되고 여러 서버 작업자 사이에 공유되지 않아 공식 경보 연결이 409로 실패할 수 있다. 운영에는 공유 저장소와 작업 버전/키 정책이 필요하다 | `Cache`, `NWS.records`, `JMA.records`, `Gemini.calls` |
| P1 | OCR이 `eng`로 고정, Tesseract 설치 여부만 확인 | 일본어 캡처 지원은 완료되지 않았다. `jpn` 언어팩과 언어 선택, 인식 결과 수정 확인, 업로드 타임아웃이 필요하다. 배포 시 ‘로컬 OCR’은 이용자 기기가 아니라 서버에서 처리된다는 설명도 필요하다 | `main.py` OCR, `services/api.ts` upload, `Flow.tsx` 설명 |
| P1 | 연결 상태가 키 문자열/플래그 존재만 검사 | ‘설정 완료’가 실제 모델 사용 가능함을 뜻하지 않는다. 관리자용 연결 테스트에서 키 없음·권한 실패·사용량 초과·통신 실패를 구분해야 한다 | `/api/health`, `App.tsx` |
| P1 | 데이터·키·위치·문자 처리 정책과 운영 배포 구성 부족 | 수집 최소화, 민감정보 제거, 보관·삭제 정책, HTTPS, 프런트/API 경로 연결, 오류 관측과 장애 대응이 필요하다. 개발용 Vite 프록시만으로 운영 구성이 완성되지는 않는다 | `vite.config.ts`, `main.py`, README |
| P2 | 단일 Flow 약 660줄, 이전 화면 코드와 상태가 중복 | 입력/조회/분석/결과를 분리하고 상태를 한곳에서 관리. 사용하지 않는 4개 페이지 정리. FastAPI OpenAPI 기반 타입/모의 응답으로 프런트엔드 작업자에게 계약 전달 | `pages/*`, `hooks/workspace.tsx`, `types/index.ts` |
| P2 | 재조회 조건 변경과 표시 결과 구분, 진행 표시, 단위·지명 표시가 불완전 | 검색 조건을 바꾸었지만 아직 조회하지 않았음을 표시하고, 요청 중에는 완료 체크를 표시하지 않도록 수정. 한국어 지역명/경보명, 현지·한국 시간, 접근성·모바일 실제 기기 시험 필요 | `Flow.tsx`, `Common.Time`, CSS |

추가 데이터 검토 항목: NWS 응답의 페이지 이동 정보 및 수집 완전성, API 장애와 실제 ‘경보 없음’의 분리, JMA 스키마 변경 감시, 지원하지 않는 재난 유형 안내, 원본 자료와 앱이 재구성한 요약 텍스트 구분. 현재 NWS/JMA 연결을 모든 미국·일본 재난문자를 포괄하는 수신 서비스로 설명해서는 안 된다.

## 5. 기능을 확장한다면

| 순서 | 기능 | 사용자에게 생기는 이점 | 선행 조건 |
|---|---|---|---|
| 1 | ‘방금 받은 문자’ 한 건 중심 화면 | 긴 경보 목록 대신 지금 온 문자의 위험·지역·시각·행동을 바로 확인 | 핵심 요약까지 검증, 원문 보존 |
| 2 | 여행 국가·숙소/도시 저장 | 반복 위치 입력 감소, 내 여행지와 관련 있는지 확인 | 위치 동의·삭제, 행정구역/경보 영역 매칭 |
| 3 | 변경·해제 알림과 이전 경보 비교 | 같은 경보의 반복과 실제 변경을 구분 | 경보 버전·만료·최신성·중복 억제 |
| 4 | 일본어 캡처 OCR와 붙여넣기 개선 | 문자 선택이 어려운 상황에서도 입력 가능 | 일본어 언어팩 및 수치/지명 인식 검증 |
| 5 | 홈 화면 설치와 저장한 안내의 오프라인 열람 | 여행 중 접속·통신 불안 편의 개선 | 저장 시각 표시, 오프라인 내용을 최신 경보로 오해하지 않게 구분 |
| 6 | 짧은 행동 체크리스트·읽어주기 | 이동 중 빠른 확인, 접근성 개선 | 검증된 문장과 읽기 순서, 음성 출력 선택 |
| 7 | 관리자용 상태 화면 | 키·잔여 앱 한도·외부 API 장애를 운영자가 확인 | 관리자 인증, 비밀/개인정보를 로그에 남기지 않음 |
| 8 | 일본 지진·쓰나미 실시간 정보 확장 | 일본 여행에서 중요한 재난 유형 추가 | 별도 공식 데이터와 변경/해제·지역 적용 로직 검증 |

다음 기능은 초기 출시에서 우선순위를 낮추는 편이 좋다: 자동 안전 경로 생성, 근거가 확인되지 않은 대피소 추천, 복잡한 여행 일정 추천, 국가를 계속 늘리는 작업. 잘못된 경로나 시설 운영 정보는 번역 오류보다 직접적인 영향을 줄 수 있다. 먼저 공식 링크와 확인 가능한 상태를 제공하는 편이 검증 가능하다.

## 6. 권장 개발 순서와 완료 기준

### A. 정확성과 실패 처리

- 사용자에게 보이는 요약·본문·지시 번역을 모두 검증한다.
- 숫자/단위·국가·시간 역할·부정 표현을 명시적인 데이터로 관리한다.
- 공식 지시, 공식 안전자료 요약, 앱의 일반 안내를 분리한다.
- AI/기상 API 실패와 정보 없음, 검증 미완료를 구분한다.
- 영어/일본어의 날짜·시간대·온도·풍속·금지/대피·경보 해제 정답셋을 만든다.

완료 기준 제안: 합의한 필수 회귀 사례에서 중대 오역/행동 반전 0건, 미검증 필드의 완료 표시 0건, AI 장애 시 원문과 일반 안내 열람 가능. 이는 정해진 시험 범위의 통과 기준이지 모든 미래 경보의 안전 보증은 아니다.

### B. 위치와 경보 수명

- 국가·도시·숙소 또는 좌표를 명확히 선택한다.
- 경보 영역과 사용자 위치의 관계를 ‘적용/미확인’으로 표시한다.
- 경보 변경/취소/만료, 조회 시각, 캐시 유효기간과 버전을 처리한다.
- 현재 선택한 경보와 다시 조회한 결과가 달라졌을 때 알린다.

완료 기준 제안: 이전 경보가 해제되어도 남아 보이는 사례 0건, 대표 지역별 적용 여부 사례 통과, API 장애를 경보 없음으로 표시하는 사례 0건.

### C. 비공개 실사용과 운영 준비

- 서버 비밀 설정을 한 번 등록하고 키 재입력 없이 사용한다.
- 세션별 제한과 공유 사용량·캐시/경보 저장소를 만든다.
- HTTPS 배포, 실패 원인별 관측, 개인정보 처리 안내, 삭제 기능을 갖춘다.
- 실제 iPhone/Android 및 느린 네트워크, 동시 접속을 시험한다.
- 소규모 사용자에게 오해한 표현·느린 단계·필요 없는 알림을 확인한다.

완료 기준은 목표 사용자 수·예산에 맞춰 정해야 한다. 최소한 다중 작업자 환경에서 경보 연결이 유지되고, 재시작으로 사용량 제한이 무력화되지 않으며, 정한 응답시간/실패율 목표를 실측해야 한다.

### D. 확장

앞 단계가 안정된 뒤 알림·오프라인·음성·새 재난 데이터를 순서대로 추가한다. 프런트엔드는 계약된 API를 유지하면서 별도로 디자인/구현할 수 있으나, 현재 큰 Flow 파일을 나누고 타입·모의 응답·오류 상태를 함께 전달하면 인수인계가 더 수월해진다.

- 기존 작업 폴더의 `work/venv` 실행 환경을 발견했다. 앞서 ‘실행 환경이 없어 백엔드 테스트를 못 한다’고 한 안내는 이 환경을 놓친 것이므로 정정한다.
- 수정 전: 백엔드 39개 중 38개 통과, 공식 지역 필드 우선 검증 1개 실패.
- 수정 후: 백엔드 **52개 통과**, 프런트엔드 **5개 통과**, TypeScript 검사·Vite 프로덕션 빌드 통과.
- Starlette/httpx 연동의 향후 변경 경고 1건이 있다. 현재 테스트 실패는 아니다.
- 로그: `docs/review-backend-tests.txt`, `docs/review-frontend-tests.txt`, `docs/review-frontend-build.txt`.
- 미검증: 실제 Gemini 응답 정확도·실시간 JMA/NWS 종단 간 현재 동작·실제 OCR·동시 사용자 부하·실제 모바일 브라우저·운영 배포·안내 문구의 재난안전 전문가 검토.

## 8. 다음 방향을 정할 때 결정할 것

1. 먼저 본인/소규모 사용자 테스트를 할지, 일반 사용자에게 공개할지.
2. 무료 API만 유지할지, 정확도·응답성·개인정보 조건을 검토한 운영 예산을 허용할지.
3. 첫 버전의 핵심이 ‘받은 문자 이해’인지 ‘내 주변 경보 자동 알림’인지. 현재 요구에는 전자를 우선하고 후자를 다음 단계로 두는 것이 맞다.
4. 일본의 첫 실사용 범위를 기상 경보로 제한할지, 지진·쓰나미까지 출시 필수 범위로 정할지.

추천안: **미국·일본의 받은 경보 해석을 중심으로, 요약/행동 검증과 지역·시각 표시를 먼저 완성한 비공개 시험판**을 만든다. 기존 UI 개선과 국가 추가는 이 기반 위에서 진행한다.
