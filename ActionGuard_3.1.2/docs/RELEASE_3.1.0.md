# ActionGuard Travel 3.1.0 · 2026-10-17

현재 작업 소스: 바탕화면 `ActionGuard-Team-Integrated`.
개발 미리보기: `/mobile-preview.html`, 앱 iframe 402 × 874 CSS px, 브라우저 100%.

## 사용자 화면
- 별도 국가 탭 대신 모든 주요 화면의 헤더에서 알림 종 왼쪽에 현재 국가 버튼. 미국·일본 선택 목록, 선택 유지, Escape/바깥 클릭 닫기. 목록 데이터에 국가를 추가할 수 있으며 실제 지원 국가는 API/위치·경보 어댑터도 구현해야 함.
- 국가를 바꾸면 이전 국가의 조회 위치와 경보·번역·AI 결과를 비우고 해당 국가 홈으로 이동. 저장한 여행 일정은 보존.
- 미국 홈에서는 일본 지진·쓰나미·화산 바로가기를 노출하지 않음. 일본 홈에서는 세 기능 제공.
- 미국은 NWS Warning / Watch / Advisory 등 원문 유형 표시. Warning을 일괄 외부 대피로 변환하지 않음. 강풍·해상 강풍·모래폭풍 등 명칭의 한국어 보조 표기 확대.
- 일본은 2026 체계의 호우·범람·토사 재해·폭풍해일에 공식 경계 레벨 상당 정보를 표시. 강풍·대설에 임의로 같은 숫자를 부여하지 않음. 쓰나미와 화산은 별도 공식 척도 사용.
- 이전 공통 4단계는 주 화면에서 제거. 기존 urgency API 계약은 하위 호환용으로 유지하고 원문 보호행동 해석에만 사용. AI가 공식 국가 등급을 바꾸지 않음.
- 대비 준비물에 등록 위치 기준 Google Maps 마트·약국·편의점 검색 링크. 클릭 전에는 Google로 좌표를 보내지 않음. 실제 재고·영업·안전 경로를 조회했다고 표시하지 않음.
- 지도 기본 탭의 불필요한 뒤로가기 제거. 지진·쓰나미에서 넘어온 명시적 연결에서는 돌아가기 유지. 가운데 챗봇 라벨 14px/굵게.

## 분화 경보
- `GET /api/japan/volcanoes`: JMA `volcano/data/warning.json`, 공식 화산 목록을 결합. 조회 시각과 발표 시각을 구분. 발표일이 오래됐다는 이유로 유효한 규제를 만료시키지 않음.
- 레벨 1~5, 숫자 레벨 미운용, 대상 시정촌, 원문 명칭, 공식 지도 연결. 명칭·코드 미지정/형식 오류는 실패로 반환하며 ‘경보 없음’으로 숨기지 않음.
- 화면 `/japan-volcano`, 전국 목록과 선택 화산. 등록 일본 위치가 있으면 직선거리 순. 거리는 위험 경계나 경로 안전을 의미하지 않음.
- 서버 푸시 Preferences에 `volcanoes` 추가. 화산 코드 검증, 최신 스냅샷·중복 발송 억제·구독 변경 시 대기 취소, 조회 실패 시 해제 알림 생성하지 않음.

## 위치 기반 푸시: 연결 코드 구현 / 실제 발송은 미검증
휴대폰 셀브로드캐스트 재난문자나 다른 앱의 알림을 읽지 않음. 등록 위치 → 공식 경보 구역 확인 → 사용자가 동의한 기기 구독 → 서버 작업자가 공식 API 조회 → APNs/FCM 발송 흐름.

- `POST /api/places/push-regions`: 미국 NWS point의 예보 구역·카운티, 일본 GSI 시정촌과 JMA 관할 구역을 사용. 모델이 구역을 만들어내지 않음.
- 알림 화면: 등록 위치/직접 지역 선택 → 일본 관측 진도 3 이상/해안/화산 선택 → 서버 구독 연결·갱신·해제.
- 실제 iOS/Android 설치 앱에서 일회용 enrollment 코드 입력 후 OS 알림 권한·기기 토큰 등록. 기존 `/api/push/devices` 인증 API와 연결.
- 관리 키는 iOS Keychain / Android Keystore AES-GCM 전용 `DeviceVault` 플러그인에 보관. 브라우저 localStorage·로그·화면에 토큰/키를 기록하지 않음. 보안 저장 실패 시 등록 취소 시도. 서버 해제 실패 시 관리 키를 버리지 않음.
- 미국 기상/화산만 구독한 기기는 일본 지진·쓰나미 조회 실패에 의존하지 않도록 분리. 일본 지진/쓰나미 구독이 존재하는 작업에서는 기존 공통 소스 실패 시 전체 작업 보류 제한이 남음.
- 웹 미리보기는 ‘휴대폰 푸시 연결 안 됨’으로 표시. PWA Web Push는 구현하지 않음.
- 서버 `disabled`/`dry_run`과 실제 발송 모드를 구별. 공급자 설정까지 준비된 경우에만 기기 연결 활성화. 공급자 접수 수를 실제 도착 수로 표현하지 않음.
- 자동 GPS 배경 추적은 하지 않음. 등록 위치 변경 후 구독 갱신을 눌러 서버에 반영. 기기 구독은 기존 30일 유효기간을 따르며 갱신 필요.

### 운영자가 준비할 것
1. 영속 비공개 DB, HTTPS 서버, CORS 출처 설정, 상시 worker.
2. APNs 또는 Firebase 실제 자격증명과 네이티브 설정. iOS Push capability/서명, Android google-services 설정. 기존 `docs/PUSH_SERVER.md` 참고.
3. 서버 환경에 `PUSH_MODE=live`, 자격증명 설정. 초기 점검은 `dry_run`으로 실행.
4. 운영자가 `python -m backend.push.worker --enroll apns` 또는 `--enroll fcm`으로 10분 유효 일회용 코드 발급. 코드는 지정한 테스트 기기에만 전달. 일반 공개 회원 가입/자동 코드 발급은 구현하지 않음.
5. `frontend/.env.mobile.example`을 `.env.mobile.local`로 복사, 실제 HTTPS API 주소 및 `VITE_PUSH_READY=true` 설정 후 `npm run mobile:sync`.
6. 실제 휴대폰에서 최초 허용/거부, 앱 재시작·토큰 변경, 구독 갱신·해제, 종료 상태/지연·중복·정정·취소를 검증. 자동 푸시 연결 코드는 추가했으나 APNs/FCM 실발송·실기기 도착은 이번 환경에서 검증하지 못함.

## 검증과 남은 작업
- 프론트엔드 162개 테스트, 백엔드 435개 통과(2개 기존 skip). 웹 타입 검사·프로덕션 빌드 성공. 기존 500kB 번들 크기 경고 유지.
- 실조회: JMA 현재 분화 경보 14개 파싱, 공식 해안 예보구 66개 코드와 선택 목록 일치 확인. 미국·일본 등록 위치 공식 구역 조회 확인.
- 402 × 874 미리보기에서 종 옆 국가 버튼과 목록, 알림 화면 확인.
- iOS 네이티브 컴파일은 Xcode SwiftPM 캐시 쓰기 권한 제한으로 완료하지 못함. iOS/Android 네이티브 컴파일·서명·설치·기기 보안 저장소 동작과 실제 푸시는 별도 검증 필요. Xcode 빌드 성공으로 표현하지 않음.
- 앱스토어/공개 서버에 배포하지 않았으며 실제 기기 구독을 만들거나 알림을 보내지 않음.
