# 팀 프론트엔드 · 기존 백엔드 통합본

작업 폴더: `/Users/moonjongjun/Desktop/ActionGuard-Team-Integrated`

이 폴더는 기존 바탕화면 `actionguard-travel`과 별도입니다. 팀원이 전달한 `ai-frontend-dev.zip`의 카드·버튼·헤더·하단 메뉴·디자인 토큰을 기반으로 홈과 대비 화면을 구성했습니다. 기존에 구현한 API 연결과 기능 모듈은 `frontend/src/integrated`에 보존하여 하나의 앱과 공통 상태로 연결했습니다. 기존 폴더는 수정하지 않았습니다.

## 실행

macOS에서 루트의 `시작.command`를 더블클릭합니다. 실행 창을 열어 두어야 합니다. 다른 실행본과 구분하여 이 폴더의 서버를 연결하고 사용 가능한 포트를 선택합니다. 실제 주소는 실행 창에 표시됩니다.

현재 설치된 의존성이 없는 팀원은 루트 README의 Python 환경과 `frontend`의 `npm ci` 설치를 먼저 진행합니다. 서버 설정은 `backend/.env`를 사용합니다. 키는 프론트엔드나 GitHub에 올리지 않습니다.

## 기능 연결 목록

| 기능 | 새 화면 | 연결 내용 |
| --- | --- | --- |
| 받은 문자 한 건 분석 | `/analyze` | 원문·국가 입력, 사진 OCR 연결, F1 번역·요약·단위 보완, F2 의미 검증, F3 공식·일반 행동지침 |
| 대응 4단계 | 분석 결과 | 기존 서버 기본 판정과 Gemini 보완, 근거·유효 상태·실내 보호 등 행동 종류 유지 |
| 미국 공식 경보 | `/analyze?mode=alerts` | 주·지역 또는 좌표 조회, 경보 선택 후 같은 원문으로 분석 |
| 일본 기상경보 | `/analyze?mode=alerts` | 일본 국가 선택, 관할 지역 조회, 한국어 지명 병기 |
| 앱 AI 도우미 | `/chat` | 경보 없이 질문, 장소 검색과 후보 선택, 조회 위치, 대피시설·일정·알림 기능 연결, 출처와 후속 질문 |
| 일정 비교 | `/itinerary` | 공통 위치·국가·시간대·체류 시간, 공식 경보와 지역·시간 비교 |
| 대피시설 | `/shelters` | 미국·일본 실제 지도, 재난 유형·거리·운영 상태, 공통 위치 등록, 오프라인 저장본 |
| 길찾기 | `/shelters?view=route...` | 지도에서 선택한 시설로 경로 연결, 도보·차량, 현재 구간 안내·진행 상태·지도 |
| 일본 지진 | `/japan-disasters?tab=earthquake` | 진앙·관측 진도 지도, 내 위치와 거리·인근 관측소 비교, 공식 원자료 |
| 일본 쓰나미 | `/japan-disasters?tab=tsunami` | 해안별 경보 지도, 단계·대상 해안·발표 상태, 시설 검색 연결 |
| 관심 지역·알림 | `/notifications` | 미국·일본 지역·재난 유형 설정 초안, 서버 작업·발송 상태, 앱 딥링크·수신 기반 |
| 사전 대비 | `/prepare` | 준비물 체크리스트, 미국·일본 현지어 SOS 카드와 긴급 연락 |

홈의 등록 위치, 분석 원문, 국가, 일정, 대화는 동일한 Workspace를 사용합니다. 분석 화면은 탭 이동 시 유지하여 원문과 진행 중인 분석을 잃지 않도록 했습니다. 공통 위치와 일정은 기존 정책대로 새로고침 시 초기화됩니다. 오프라인 시설 저장과 알림 설정 초안은 별도 선택 저장입니다.

## 통합에서 수정한 부분

- 휴스턴 예시를 현재 위치로 표시하거나 조회에 강제로 사용하는 팀원 임시 코드를 실행 경로에서 제거했습니다.
- 팀원 임시 대피 키워드 판단을 사용하지 않고 기존 백엔드의 대응 단계·행동 판단을 연결했습니다.
- 챗봇을 경보 입력 없이 사용할 수 있게 하고 서버의 장소 후보, 결과 항목, 지도·일본 재난·알림 경로를 유지했습니다.
- 도우미와 기상 알림에서 문자 분석으로 들어오는 경로를 새 `/analyze` 화면에 맞췄습니다.
- 지도와 길찾기는 기존 실제 지도 모듈을 사용합니다. Google Maps API 키는 필요하지 않습니다.
- 기존 기능 스타일을 `.integrated-feature`에 한정해 팀원 화면과 충돌하지 않게 했습니다. 원본 스타일을 수정한 경우 `npm run sync:styles`를 실행합니다. 빌드 전에도 자동 실행됩니다.

`frontend/design-reference`에는 전달받은 원래 화면·임시 서비스 코드를 참고용으로 보관했습니다. 이 디렉터리는 실행·빌드·테스트 대상이 아닙니다. 실제 엔트리는 `frontend/src/index.tsx`, 라우팅은 `frontend/src/App.tsx`입니다.

## 실제 사용 전 남아 있는 기존 제약

- 실제 APNs/FCM 기기 구독과 휴대폰 수신 검증, 앱 서명·APK/IPA 배포는 아직 완료되지 않았습니다. 화면에서 알림을 저장했다고 푸시가 활성화된 것은 아닙니다.
- OCR 화면과 API는 연결되어 있으나 로컬 Tesseract 실행 파일이 설치되어야 사진 인식이 동작합니다. 이번 실행 환경에서는 `ocr_available=false`였습니다. 현재 서버 OCR은 영어 인식 설정입니다. 일본어 사진 인식은 별도 언어팩·설정 검증이 필요합니다.
- Gemini 키와 제공자 응답 상태에 따라 번역·AI 답변이 실패할 수 있습니다. 공식 조회와 일반 행동요령은 AI와 별개로 확인할 수 있습니다.
- 경로는 일반 경로이며 재난 시 통행 가능·안전 경로를 보장하지 않습니다. 시설 지정 정보도 현재 개방 확인을 대신하지 않습니다.
- 내 위치의 예상 진도를 만들어 표시하지 않습니다. 공식 관측값과 주변 관측소 자료의 범위를 구분합니다.

모바일 빌드는 기존 `capacitor.config.json`, `ios`, `android` 프로젝트를 포함합니다. 실제 HTTPS 서버 설정 후 `npm run mobile:sync`로 새 웹 화면을 동기화해야 합니다.

## 이번 통합 검증

- 백엔드 391개 통과·2개 건너뜀, 프론트엔드 119개 통과. 빌드와 새 UI 정적 검사 통과.
- 기존 백엔드 Python 소스 60개와 비교해 변경 없음.
- 미국 공식 경보 조회, 일본 지역 목록·지진·쓰나미, 도쿄역 예시 주변 시설 및 OSRM 일반 경로 응답 확인.
- 경보 없이 앱 AI 도우미의 기능 안내 응답과 연결 버튼 확인.
- 개인정보 없는 미국·일본 훈련용 예시 문자의 실제 Gemini 번역 응답 확인. 일본 첫 요청은 HTTP 502였고 재시도에 성공함. 반복 품질 평가나 출시 승인을 의미하지 않음.
- 상세 결과는 `INTEGRATION_VALIDATION.json`과 `integrated-*.txt`에 기록.
