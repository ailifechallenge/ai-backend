# 문자 평가 세트 v1 — 2026-10-15

## 자료 구분과 개인정보

12개 표본: 미국 공식 기상 브리핑 발췌 1개, 일본 지자체 공개 안전메일 발췌 1개, 일본 오발송 공지 발췌 1개, 합성 회귀 표본 9개. 미국 브리핑은 실제 휴대전화 수신 문자라고 주장하지 않습니다. 개인이 받은 실제 SMS 원본은 제공되지 않았습니다. 공공 지역명과 사건 날짜는 유지하고 연락처·페이지 하단·개인정보는 포함하지 않았습니다. 발췌 범위를 넘어선 날짜나 시간대는 정답에서도 추정하지 않습니다.

각 표본에는 origin, source_url, privacy, gold, tags를 기록했습니다. 정답은 개발 에이전트의 1차 검토이며 재난/언어 전문가의 독립 승인 전입니다. 날짜, 발령·발생·시작·종료, 지역, 단위, 부정문, 복합 재난, 해제, 훈련, 오발송을 포함합니다. 상대 날짜 및 모르는 시각은 null 또는 미상 설명으로 유지합니다.

## 실행

프로젝트 최상위에서 가상환경 Python으로 실행합니다. .env에는 키와 무료 티어 확인 설정이 필요합니다. 키 내용은 커맨드나 결과에 넣지 않습니다.

```bash
python -m evaluation.run --env /path/to/backend/.env --output evaluation/runs/new-run
```

기본 대표 4건 × 2회(32호출), 첫 회 오류 주입 2건(6호출) = 최대 38호출입니다. `--ids`, `--repeat`, `--max-calls`, `--skip-mutations`로 제한합니다. 이전 결과를 덮어쓰지 않으며 새 디렉터리를 요구합니다. 429 또는 다른 실패 시 즉시 중단하고 자동 재시도·유료 모델 변경을 하지 않습니다. 실패 전 번역과 실패 단계도 다음 실행부터 별도 보존합니다. 여러 실행을 합한 호출량은 운영자가 관리해야 하며 프로세스를 다시 켠다고 제공자 한도가 늘어나지 않습니다.

결과는 원문 정답과 모델 출력, 인용 근거, 오류 주입 탐지 결과를 보존합니다. 실행 시 데이터/코드 해시와 모델을 저장합니다. 2026-10-15 최초 평가에는 코드 해시 자동 기록이 없으므로 evaluated-code-sha256.json에 당시 비교용 파일 해시를 별도 기록했습니다. 이후 수정본과 동일한 실모델 평가로 간주하지 않습니다.

## 평가 기준

- 요약 중대 오류: 날짜·시간 역할·지역·수치·단계·부정·행동 조건의 변경, 원문에 없는 긴급 행동 추가. 단순 생략은 허용하되 금지/대피 조건 등 의미를 뒤집는 생략은 오류입니다.
- 의미 검증 누락: 정답 검토에서 확인한 중대한 오류를 critical로 지적하지 못한 경우. clean 문장을 평가한 결과와 오류 주입 결과를 분리합니다.
- 운영 실패: 형식 오류, API 실패, 한도, 타임아웃. 완성된 결과만 분모로 삼아 실패를 숨기지 않습니다.
- 모호한 표현과 불확실성을 숨기지 않는지 별도 검토합니다. `불일치 미탐지`는 정확성 인증이 아닙니다.

## 출시 게이트 제안

현재는 HOLD입니다. 국가별 실제 경보/문자와 긴급 유형을 균형 있게 확보하고 최소 100개 서로 다른 표본을 3회 이상 평가해야 합니다(통계적 안전 보증을 의미하지 않는 내부 최소 기준). 독립 검토자가 정답/출력을 검토하고, 중대 오류 및 오류 주입 누락은 0건, 분석 완료율은 99% 이상을 목표로 합니다. 기준 충족만으로 자동 출시하지 않으며 행동지침 전문가 검토와 모바일 실기기 검증도 필요합니다. 현재 작은 세트는 버그 발견용으로만 사용합니다.
