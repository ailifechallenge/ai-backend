# 기존 프로젝트 검토

첨부 ZIP의 21개 파일(소스·테스트·README·환경 예시·설정)을 읽고 기존 20개 테스트를 실행했습니다. 정상 통과했습니다. ZIP 안 설명은 기존 구현 자료로만 사용하고, 붙여넣은 개발 지시서를 작업 요구사항으로 적용했습니다.

## 재사용과 변경

- 기존 httpx Gemini REST, JSON schema prompt, Pydantic 검증 패턴은 유지하되 비동기로 재구현했습니다. HTTP 오류에서 응답 본문을 노출하지 않는 설계를 유지했습니다.
- `normalize_quote`, `supported_quote`, 영문/한국어 시각 추출 함수를 `backend/core/quotes.py`로 재사용했습니다.
- 기존 가상 경보 fixture를 보존했습니다.
- Streamlit 전용 상태/키 입력/캐시를 제거하고 React 메모리 상태 + 서버 환경변수 + TTL 캐시로 분리했습니다.
- 기존 requirements와 imports에 OpenAI 실행 의존성은 없었습니다. 새 프로젝트에도 없습니다.

## 발견한 부족한 부분

1. 기존 NWS 어댑터는 동기 요청·좌표 조회만 지원. 중복 제거와 발령기관/발령시각 필드가 부족했습니다. 새 어댑터는 주/좌표, 중복 제거, 120초 캐시, 20초 타임아웃을 지원합니다.
2. 기존 규칙은 시각 차이를 미해결로만 반환했고 빈 추출도 미탐지로 끝날 수 있었습니다. 새 엔진은 빈 추출의 검증 불가, 시각 차이 및 특정 금지 반전의 오류 카드, 일부 단위/날짜/용어/지역 보존 검사를 추가했습니다.
3. 기존 추출 유형에서 필수/권고 행동, 시작/종료 시간, 단위/부정이 분리되지 않았습니다. 새 Pydantic 스키마는 12개 유형을 구분합니다.
4. 기존 OCR은 Gemini 비전 호출이었습니다. 무료 오픈소스 우선 요구에 따라 Tesseract 로컬 OCR로 전환했습니다.
5. 기존 F3는 네 가지 자료 링크 중심. 새 UI는 공식 원문 지시를 우선하고 6개 재난군의 요약/조건/기관/검토일/출처를 별도 표시합니다.
6. 실 NWS 데이터에서 expires와 headline 종료시각이 다름을 확인했습니다. expires를 현상 종료로 해석하지 않도록 onset/ends와 분리했습니다.

## 구조와 운영 선택

FastAPI 경로는 main.py에 모으고 핵심 처리는 core/adapters/models로 분리했습니다. 메모리 캐시는 유한 크기와 TTL을 가지며 사용자 로그인·유료 DB·Redis를 도입하지 않았습니다. 공식 출처를 클라이언트가 선언하게 하지 않고 서버 캐시의 원문 일치로 확인합니다. 공개 배포나 과금 설정 변경은 수행하지 않았습니다.


## F1~F3 통합 화면

기존 Dashboard → Translate → Verify → Guidance 네비게이션을 하나의 작업 화면으로 합쳤습니다. 사용자는 NWS 활성 경보를 선택하거나 원문/캡처를 한 번 제공한 뒤, 통합 실행 버튼을 누릅니다. 프론트엔드는 F1 번역, F2 검증, F3 지침을 순서대로 호출하고 단계 표시와 결과를 같은 페이지에 나타냅니다. NWS 경보 탐색은 입력 화면의 탭 안에서 사용할 수 있고, 공식 정형 필드 및 원문 인용 비교는 접을 수 있는 세부 영역으로 배치했습니다.

참고한 Figma 화면의 모바일 우선 입력, 단일 주요 CTA, 단계 진행 표시, 차분한 파랑 계열 상태 강조를 적용했습니다. 참고 사이트의 안내 문구나 시연 결과를 그대로 복제하지 않고 기존 NWS/Gemini 백엔드 동작에 맞춰 구성했습니다.
