# 경보 질문 챗봇 + 일정 한 건 판정 — 2026-10-15

## 구현한 흐름

1. 경보를 조회해 선택하거나 받은 문자를 입력합니다.
2. 숙소·방문지의 이름, 좌표 또는 일본 시정촌, 현지 시간대, 체류 시작·종료를 입력합니다.
3. ‘장소 등록하고 겹침 확인’을 누릅니다. 공식 경보와 연결되지 않은 문자는 판정 불가로 표시합니다.
4. ‘이 경보에 질문하기’에서 자유 질문 또는 추천 질문을 선택합니다. 일정 질문은 등록된 일정과 공식 경보를 서버 규칙으로 비교합니다.

장소 이름을 자동으로 좌표로 변환하는 기능은 이번 버전에 없습니다. 지도에서 확인한 위도·경도 또는 ‘현재 위치로 채우기’를 사용합니다. 일본 공식 경보를 선택하면 경보에 포함된 시정촌을 직접 확인해 선택할 수도 있습니다. 현재 위치가 예약한 숙소 위치를 뜻하지는 않습니다.

일정과 대화는 화면 메모리에만 유지합니다. 새로고침하면 지워집니다. 경보 변경 시 대화·판정은 초기화하고 입력 중인 일정은 유지합니다. 일정 변경 시 기존 판정을 무효화합니다. 입력한 시간은 기기 시간대가 아닌 사용자가 선택한 장소의 현지 시간대로 해석합니다. 미국 주요 시간대와 Phoenix, 일본 Tokyo를 지원하며 서머타임으로 없거나 두 번 나타나는 시각은 요청을 거절합니다.

## F4 판정 범위

- 미국 NWS 응답의 GeoJSON Polygon/MultiPolygon을 보존하고 좌표와 비교합니다. 안쪽 구멍은 제외하며, 경계 위·날짜변경선·극지·지원하지 않는 구조는 확정하지 않습니다.
- 공식 경계 안이며 onset/ends와 체류 시간이 겹칠 때만 ‘겹침 확인’입니다.
- 경계가 없으면 NWS 좌표 조회에 동일 ID·동일 원문 경보가 있는지 보조 확인합니다. 이 경우 정밀 경계 확인으로 간주하지 않고 ‘겹칠 가능성’입니다. 조회에서 안 보인다는 이유만으로 겹침 없음으로 판정하지 않습니다.
- 일본 시정촌 일치는 넓은 지역 비교이므로 ‘겹칠 가능성’까지만 표시합니다. 일본 원문에서 시작·종료 시각을 임의 생성하지 않습니다.
- 공간 또는 명시된 시간의 불일치는 ‘현재 확인된 겹침 없음’이며 안전 판정이 아닙니다. 다른 경보나 이동 중의 위험도 판정하지 않습니다.
- 메시지 만료, 공식 취소, 오래된 조회 정보를 구분합니다. 15분보다 오래된 조회는 재조회가 필요합니다. 최초 조회 이후 갱신을 자동 추적하지는 않습니다.
- 호텔 주소 자동 검색, 경로 판정, 자동 알림, 계정·영구 저장은 미구현입니다.

## 챗봇

- 선택한 경보 원문과 서버에서 선택한 공식/일반 지침만 근거로 사용합니다.
- 공식 경보의 시각 질문, 일정 판정 답변은 모델을 호출하지 않습니다. 미등록 일정은 등록을 요청합니다.
- 자유 질문은 답변 생성 1회 + 근거와 답변 의미 검토 1회로 최대 2회 모델 호출합니다. 기존 F1~F3 전체를 재실행하지 않습니다.
- 모델에는 출처 ID만 부여합니다. 실제 URL은 서버가 연결하며 인용이 해당 자료에 존재하는지 검사합니다. 인용 오류 또는 의미 검토 실패는 답변 대신 확인 불가를 반환합니다.
- 같은 모델을 두 번 사용하는 검토이며 독립 정확성을 보증하지 않습니다. 안전 판정·이동 경로·시설 운영·근거 없는 행동 명령을 답하지 않도록 제한했습니다.
- 대화는 최대 최근 4쌍을 전송합니다. 원문·질문·대화와 필요한 지침은 Gemini에 전달됩니다. 일정 좌표·시간은 모델에 전달하지 않습니다. 사용자가 질문에 직접 적은 개인정보는 질문에 포함되므로 입력하지 않아야 합니다.
- 일반 질문을 자동 검색이나 새로운 사실 조사로 확장하지 않습니다. API 실패·한도 초과 시 기존 경보와 일정 화면은 남고 오류를 표시합니다.

## API / 인계

- `POST /api/conflict`: 기존 Input + stay. 결과 status, reasons, spatial, temporal, checked_at, source, interval_utc.
- `POST /api/chat`: 기존 Input + question, history(선택), stay(선택). 결과 answer, sources(title/quote/url), checked_at, mode.
- 공식 경보 ID는 서버 캐시에 연결되고 원문이 일치해야 합니다. 클라이언트가 지리 정보나 판정 결과를 공식 데이터처럼 제출할 수 없습니다.
- Alert에 선택적 geometry, message_type 필드를 추가했습니다. 기존 클라이언트와 호환됩니다.
- 프론트엔드는 TravelAssistant 컴포넌트로 분리해 이후 UI 교체가 가능합니다.

## 검증 결과 및 한계

백엔드 96개, 프론트엔드 10개 통과. TypeScript 및 배포 빌드 통과. 핵심 검사는 시간 겹침/비겹침, 미상 종료, 시정촌 일치, 만료·취소, 다각형 구멍·경계, 서머타임 중복/누락 시각, 위조 출처 거부, 근거 없는 답변 거부, 일정 편집 후 무효화, 다른 경보의 지연 응답 제거입니다.

신규 챗봇의 실 Gemini 응답 및 실시간 NWS 좌표 조회는 이번 검증에 포함하지 않았습니다. 모델 검토는 모의 응답으로 검사했습니다. 로컬 미리보기 서버는 실행 환경에서 포트 열기가 제한되어 브라우저 육안 검증을 완료하지 못했습니다. 실제 모바일·실모델 평가와 공식 지리 데이터의 다양한 형태에 대한 추가 검증이 필요합니다. 공개 출시 보류 상태를 유지합니다.

공식 경보 API 근거: https://www.weather.gov/documentation/services-web-api

배포 ZIP에는 실제 API 키를 포함하지 않습니다. Desktop 실행본의 기존 .env는 유지하고 새 코드 적용 후 서버를 재시작해야 합니다. 이번 작업은 작업 폴더 및 ZIP을 변경했으며 Desktop 복사본은 변경하지 않았습니다.
